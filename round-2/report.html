1. Approach: Methodology and Architecture

1.1 Overview

Our solution uses a 3-model gradient-boosted tree ensemble (LightGBM + XGBoost + CatBoost) with rank averaging, trained on 208 engineered features across transaction, static account, and graph-based feature families. We employ multi-round confident learning for label noise detection and heuristic noise scoring for red herring avoidance.

1.2 Feature Engineering (208 features)

Features are computed in 4 passes over the 16GB dataset using memory-efficient batch processing:

PassCategoryCountDescription
1Transaction Core~100Volume, amounts, temporal histograms (hourly/daily/monthly), channel diversity, MCC patterns, counterparty fan-in/out, structuring detection, behavioral change
2Transaction Extended~40Geographic spread, IP diversity, balance statistics, transaction type distributions, dormancy patterns
3Static Account~35Account age, freeze history, customer demographics, branch characteristics, scheme codes, product details
4Graph~33PageRank, HITS scores, betweenness centrality, Louvain community detection, clustering coefficients, component sizes

1.3 Label Cleaning

  • Confident Learning (2 rounds): Out-of-fold LightGBM probability estimation with per-class thresholds (Northcutt et al. 2021). Identifies samples where model confidence conflicts with the label.
  • Heuristic Noise Scoring: Rule-based detection targeting 7 red herring categories. Assigns noise scores based on metadata signals.
  • Combined Weights: max(CL score, heuristic score) mapped to sample weights in [0.2, 1.0].

1.4 Model Training

  • Ensemble: LightGBM + XGBoost + CatBoost, each trained independently
  • Cross-validation: 3-seed (42, 43, 44) x 5-fold stratified CV for stability
  • Encoding: Frequency encoding for categorical features (safe, no label leakage)
  • Hyperparameters: Optuna-optimized (100 trials per model). Best params use near-zero regularization.
  • Ensemble method: Rank averaging outperformed simple averaging, weighted averaging, and stacked meta-learning.
  • Class imbalance: scale_pos_weight = 34 (matching ~2.8% mule ratio)

1.5 Temporal Window Prediction

For accounts predicted as mules, we analyze transaction history using a sliding window approach, scoring each window by anomaly density and selecting the window with the highest concentration of suspicious patterns.

2. Key Findings: Mule Account Patterns

2.1 Top Discriminative Features (SHAP Analysis)

  • Transaction volume: Total count and unique counterparties are the strongest signals.
  • Graph centrality: PageRank and betweenness capture mules as network intermediaries.
  • Channel diversity: Mules use more diverse transaction channels.
  • Temporal patterns: More off-hours activity and irregular temporal patterns.
  • Structuring indicators: Near-threshold amounts are a strong mule signal.
  • Balance behavior: Rapid credit-debit cycles (pass-through behavior).

2.2 Mule Behavioral Archetypes

  • Pass-through mules: High velocity credits followed by rapid debits, minimal balance retention
  • Network hubs: High fan-in/fan-out with many unique counterparties
  • Dormant-burst: Long inactivity followed by sudden intense transaction bursts
  • Structuring mules: Deliberately fragmenting amounts below monitoring thresholds

7Flagged by own branchBranch features carry both signal and noise0.000
RH7 Analysis: Branch-related features allow the model to learn the spurious "flagged by own branch" pattern. Removing all branch features achieves RH7=1.000 but drops AUC from 0.956 to 0.893. The branch features carry genuine discriminative signal that outweighs the RH7 penalty. A more nuanced solution would require decorrelating the RH7 signal from branch features without losing predictive power.
